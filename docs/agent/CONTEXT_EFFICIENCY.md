# Context & Token Efficiency（上下文与 Token 效率）

> 本文规定 Codex 维护本仓库以及未来 JavaFix Agent 运行时应遵循的上下文控制规则。
> 它不改变当前 Phase 3 的范围；Python Agent 运行时仍须在用户批准进入 Phase 4 后才可实现。

## Core Rule（核心规则）

使用完成当前任务所需的**最小必要上下文（Minimum Necessary Context）**：当前会话只保留短期任务信息，长期稳定事实写入项目文档；不把聊天历史、推理过程、完整命令输出或整份源码当作项目记忆；复用已确认且未变更的结论。

## Locate Before Read（先定位，再读取）

默认流程：

```text
Understand → Locate → Read minimum context → Plan → Implement → Test → Summarize → Handoff
```

读取顺序如下；只有证据不足时才扩大范围：

1. 当前目标文件；
2. 其直接调用方、直接依赖或接口；
3. 对应测试；
4. 必要配置、数据结构与项目状态文档；
5. 任务明确要求的更大范围。

规则：

- 先用文件名、符号、错误信息或调用关系搜索，再精确读取相关片段。
- 对大文件优先定位类、方法、接口与错误附近内容；不因小改动重新读取整份文件。
- 不默认扫描整个仓库、全部测试、全部文档或完整 Git 历史；架构审查等明确任务除外。
- 日志只保留结果、关键错误、失败位置与必要诊断，避免将构建、依赖安装或测试的完整输出带入上下文。

## Context Budget（上下文预算）

上下文用量可见时，按以下阈值收缩工作范围；不可见时，以“是否仍可清晰持有当前原子任务”作保守判断。

| 使用率 | 工作方式 |
|---|---|
| 0%–40% | 正常执行。 |
| 40%–55% | 停止非必要读取，优先复用已验证结论。 |
| 55%–70% | 完成当前原子任务后写入状态摘要并准备交接。 |
| 70%–85% | 禁止大范围扩展上下文，只读取解决当前阻塞所必需的信息。 |
| 超过 85% | 不再载入大块内容；先压缩状态并切换到新会话。 |

任务本身需要全仓分析时，应明确说明范围、分批调查，并只保留结论和证据。

## Tool, Change, and Test Discipline（工具、修改与测试纪律）

- 工具调用必须降低不确定性；已有可靠结论时停止重复搜索或调用多个工具取得同一信息。
- 修改保持最小化，不借机重构、升级依赖或调整无关代码。
- 测试从窄到宽：目标测试 → 模块测试 → 仅在需要时执行完整套件。
- 工具输出只在最终说明中保留关键结论，不能复制大段原始输出。

## Output and Handoff（输出与交接）

默认输出顺序为：结果、关键修改、验证状态、风险或下一步。除非用户要求，不重述完整需求、粘贴完整文件或写成教程式过程说明。

长任务或会话结束前：

1. 完成可独立验证的当前原子任务；
2. 运行相关验证；
3. 更新 [`CURRENT_STATUS.md`](CURRENT_STATUS.md)；
4. 记录未解决事项和唯一明确的下一步；
5. 新会话从项目规则、`CURRENT_STATUS.md` 和下一任务的直接依赖继续，不重建完整聊天历史。

`CURRENT_STATUS.md` 只保存：当前目标、已完成内容、重要决策、主要改动文件、测试状态、已知问题、下一步及继续任务必读的文件。不得写入聊天记录、推理轨迹、大段日志、废弃方案细节或复制的源码。

## Runtime Implementation Note（运行时实现说明）

未来 Agent Runtime 应将 `files_read`、`token_usage`、`steps` 与 `task_success` 作为可观测指标；这些指标的实现属于已规划的后续阶段，本文不授权在 Phase 3 添加 Python 运行时代码。
